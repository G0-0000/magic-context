# v0.49.20

## Fixed

- Oh My Pi now keeps Magic Context's `ctx_*` tools at the top level with their complete descriptions and schemas instead of hiding them behind the `xd://` catalog. Missing `ctx_reduce.drop` arguments now show an example range. Thanks @TheOrdinaryWow for the report and transcript scan.
- Failed historian and dreamer attempts now show their attempted model and sanitized host error in the Historian tab; unknown configured models warn once per process.
- The local embedding provider now follows each model's declared pooling and normalization, keeping BGE vectors aligned with the sentence-transformers pooling rule; memories and git commits re-embed in the background, while inactive-session history vectors stay out of semantic search until that session runs `/ctx-embed start` (issue link: [753](https://github.com/cortexkit/magic-context/issues/753), thanks @LouisLau-art).
- On OpenCode 2, Magic Context's memory use no longer grows with every session opened since the server started; its saved copies for side questions are now capped (#764, thanks @null-axiom).
- Primary sessions on OpenCode 1, OpenCode 2 and Pi no longer strand queued reductions below force pressure. If only the current user prompt prevents summarization, the next pass may summarize past that prompt once, retaining normal token limits and tool-call boundaries. Otherwise, when no summary is running or waiting to render, execute can apply eligible reductions and cleanup in one rebuild after 2% reclaim or three consecutive held execute passes. Signed-thinking safety remains in force. Rust mode is unchanged.
- Dreamer now detects first model activity on OpenCode 2, Pi and Oh My Pi. A completely silent primary with a configured fallback is cut after 90 seconds, giving the fallback the remaining task time; a primary that streams text, reasoning or a tool call keeps its full timeout. The invocation record says why a silent attempt was stopped.
- Semantic auto-search hints in long sessions with many stored history vectors no longer time out on almost every turn. When a hint reached its one-second deadline, the background search was thrown away together with the history vectors it had loaded, so every turn started cold and a session with about 20,000 stored vectors could never finish loading them. Now the deadline only stops the wait: the search finishes in the background and keeps its vectors for the next turn. The vectors are kept up to date between turns, reading only new or changed ones, and a turn whose vectors are not loaded yet goes ahead without them instead of waiting. A search that misses its deadline now logs how long each step took. Hints now also list their fragments by relevance, the log shows the relevance score of an attached hint, no background memory step runs when memory is turned off, and a cancelled `ctx_search` stops loading history vectors (issue 762, thanks @null-axiom for the report and the detailed trace).
