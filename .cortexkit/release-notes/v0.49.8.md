# v0.49.8

This patch release makes history replay more reliable, applies historian limits consistently, and reduces what diagnostic reports share. There is no database migration.

## Upgrading

- **No migration.** `context.db` stays at schema 95 and `store.db` at schema 63. Restart OpenCode 1, OpenCode 2, Pi or Oh My Pi after updating.
- **Some OpenCode 2 sessions have a one-time request-byte change.** Previously omitted host instructions are now retained when replaying summarized history. This can change the cached request prefix once after upgrading; subsequent replays keep those instructions stable (#702).

## Fixed

- **Historian output limits apply to every recompression and wrapup path.** Automatic runs, manual commands and RPC requests now consistently honor `historian.maxTokens`, including Pi and Oh My Pi (#701).
- **OpenCode 2 can replay summarized history when its boundary message is outside the current message window.** A boundary that still exists in the host database can be placed using its saved order, including after moving a session or deleting unrelated old rows. Unsummarized instruction updates remain in the request, and repeated replays do not bring the old history back. Recovery commands also reach the plugin instance for the session's current project (#702).
- **Dropping tool history no longer mutates the host's live tool-call objects.** Replayed reductions use copies, so later turns see the same trimmed history without corrupting a tool call that is still in progress (#703).
- **Background workers and timers no longer retain an old request's async state.** Shared resources are created outside request-local scopes, preventing old request data and stale write guards from staying attached to long-lived background work (#707).
- **OpenCode 2 no longer returns the first message for an ordinal beyond the end of a session.** `ctx_expand` reports that the requested message or range is absent, or returns an available search-archive excerpt instead of mislabeling unrelated source text.
- **Successful prepared database statements no longer consume the time reserved for waiting on a writer lock.** Foreground work retains its lock-wait budget when a statement is slow but uncontended, while contended writes still share a bounded wait.
- **`doctor --issue` reports share less private information on every host.** OpenCode, Pi and Oh My Pi reports use consistent aliases for paths and identifiers and omit free text, source content and tool content. Recent error diagnostics are retained separately from the log tail. Review the generated report before sharing it.
